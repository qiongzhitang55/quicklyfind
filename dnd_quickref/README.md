# dnd_quickref — 法术速查填表工具

纯 Dart：本地服务 + 浏览器界面。一条链路走完：

**左边搜法术 / 词条 → 中间看规则 → 抓进最右边的备选区 → 从那栏选表格、一键填入。**

基准卡是用户给的 **v1.0.12** 版（`card\空白卡v1.0.12.xlsx` 当模板，`card\悲灵.xlsx` 当默认目标表）；
`card\空白卡.xlsx` 是更早的 v1.0.0 版式，主要表格子位置不同，只留作参考。

## 三种页面

树里的节点不是一种模板套到底，按内容分三类：

| 类型 | 用在 | 长什么样 |
|---|---|---|
| **词条页** | 法术 / 职业特性 / 种族特性 / 专长 | 左列表 + 中详情，查出来「+」进最右边的备选区，再从那儿一并写进表 |
| **表单页（带速查）** | 魔法物品 | 上半是规则书速查（搜 307 条魔法物品，`+` 进备选区、点开看全文），下半是卡里那几块的编辑格 |
| **规则页** | 起源的种族 / 背景、职业的主职业 / 等级 | 内容全来自规则书：卡里自己算的只显示，要自己挑的勾一下 → 进最右边的备选区 |
| **表单页** | 基本信息 | 分组卡片，一格一个字段，按字段类型给控件（文本 / 数字 / 下拉） |
| | 属性与技能 | 表格版式：6 行属性 + 17 行技能，勾选格写 `X/O`，卡算出来的格子只读展示 |
| **占位页** | 还没做的节点 | 空白占位 |

### 表单页：基本信息

写进「主要」表，字段与落点：

| 分组 | 字段 | 格子 |
|---|---|---|
| 身份 | 角色名 / 玩家 | `E3` / `E4` |
| 等级与职业 | 主职业 / 子职业 / 等级 / 经验值 | `E6` / `I6` / `O6` / `E9` |
| 兼职 | 兼职1 职业 / 子职 / 等级 | `E7` / `I7` / `O7` |
| 起源 | 种族 / 亚种 / 出身 / 阵营 / 信仰 | `T6` / `T7` / `起源!E6` / `T8` / `T9` |

出身写的是卡里的「起源」表（不在「主要」表），所以这一页会跨两张表写。
控件按字段类型给：职业 / 子职业 / 种族 / 亚种 / 出身 / 阵营都是下拉，选项全部来自卡自己
（见下面「车卡的选项从哪来」），等级和经验是数字框，其余文本。
每个字段右边灰字标着它写进哪一格。写入前照例自动备份，只改动的格子，公式格一律不碰。

下拉里只放**基本那一份**：职业是卡里列的那 19 个，出身是核心那 16 条——卡里还挂着几十条
扩展书的出身（剑湾、拉尼卡、斯翠海文…），那些手输照样能填，只是不塞进下拉。

选中子职业、选中出身时，表单底部会出现对应的**规则正文卡片**（见下面「子职 / 出身的规则正文」）。

**这一页填的东西不直接落表，先进最右边的「备选区」**（见下面「备选区」一节）。
表单页都没有单独的「写入表格」按钮，写表统一走备选区。

### 表单页：属性与技能

两块表格，列头就是卡里的列：

- **六项属性**（行 13–18）：熟练 `B`（`X/O`）、初始值 `I`、背景 `K`、成长 `M`、修正 `O` 可填；
  总值 `F`、调整值 `R`、豁免 `T` 是卡自己算的，只读显示
- **技能**（17 项，行 41–61）：熟练 `B`（`X/O`）、额外修正 `F` 可填；总值 `I` 只读

只读格和行标签列永远不会被写入——写进去就把卡里的公式覆盖了。

```
┌──────────┬────────────┬──────────────────────┬────────────┐
│ 设计树    │ 法术列表    │  法术详情             │  备选区     │
│ 车卡顺序  │ 搜索+筛选   │  规则正文             │  待填清单    │
│          │            │  [+ 抓进备选区]       │  ──────────  │
│          │            │                      │  目标表格    │
│          │            │                      │  新建/使用已有│
│          │            │                      │  [填入表格]  │
└──────────┴────────────┴──────────────────────┴────────────┘
```

**页内填入区已经取消**：不论哪一页，抓到的东西都进最右边那一栏。选表格、查重、
一键写入也都集中在**备选区**里（详见下面「备选区」一节）。

顶上那一条是**车卡进度**（`GET /api/form` + `GET /api/page` + `GET /api/table` 现算的）：
角色名 / 种族 / 亚种 / 出身 / 阵营 / 主职业 / 子职业 / 等级 / 六项属性填了几项 /
技能熟练（对得上职业正文里「选择 N 项」）/ 专长还能选几个（按 4·8·12·16·19 级）/ 法术位还剩几格。
填好的绿、还没填的黄，点一下跳到对应页面。卡里模板预填的 `10` 算「还没动」。

## 设计树

最左边是整张人物卡的设计树，**按车卡顺序**排；点节点切页面。★ 是已经做好页面的节点，
其余点进去是空白占位。节点后面那行灰字，是它在卡里对应的实际工作表名。

```
基本信息   主要       单节点：点开就是那张表单（身份 / 等级与职业 / 兼职 / 起源＋出身）★
起源       起源       种族 ★ · 背景 ★（种族 / 背景分上下两行，都只读种族与出身）
职业       主要       主职业 / 子职业 ★ · 职业特性 ★
属性与技能 —          已删：六项属性 / 豁免 / 技能 / 工具都并进第一页「基本信息」
专长       主要       专长 / 属性提升 ★
装备与背包 背包       武器 / 护甲 / 盾 ★ · 物品 / 货币 · 负重 ★
魔法物品   主要       单节点：上面速查（307 条魔法物品）+ 下面卡里那几块 ★
法术       法术书     法术列表 ★
全部速查   —          法术 / 职业特性 / 专长 / 种族特性 / 魔法物品一起搜 ★
```

> 「魔法物品」下面那四条（武器 / 护甲 / 盾 / 奇物 / 已同调的装备）合并成了**一条**：
> 点它就是整页——上面速查、下面卡里那几块。设计树不再为同一页挂四行。

**pane 的长宽都能拖**：设计树 / 列表 / 备选区三条竖线、以及「魔法物品」速查块的右边和下边，
鼠标按住拖就行；松手会把尺寸记进 `localStorage`，下次打开还是这个大小。

## 全部速查

设计树最末尾那一条，把五类词条（法术 798 / 职业特性 2080 / 专长 229 / 种族特性 493 /
魔法物品 307，共 3907 条）放在一起搜：左边列表（每条标着它属于哪一类）、中间看正文、
右边「+」抓进备选区。筛选面是**类型**和**来源**。

备选区里每一条都记着自己属于哪一类，点「填入表格」时**各走各的落点**：
法术 → `法术书` 的法术位、职业特性 → `主要` 的特性列、种族特性 → 种族特性列、
专长 → 专长列、魔法物品 → 奇物名那一列。同一次点「填入表格」可以混着写。

「基本信息」原来拆成「姓名 / 等级 / 经验」和「职业 / 起源 / 阵营」两条，点进去是同一张表，
已经合成一个节点（「外观 / 性格」那条占位删了）。别的分支还有同一张表挂两条的情况
（起源的「背景」和「语言 / 熟练」、装备的「武器」和「负重」、魔法物品的四条…），要合也照这个来。

**「属性与技能」下面那三行**（六项属性 / 豁免 · 熟练 / 技能 · 工具）也删了：
它们本来就是同一张表，现在直接并进第一页「基本信息」——身份 / 等级与职业 / 兼职 / 起源
后面接着就是六项属性表和技能表，一页填完。**「属性与技能」这一行本身也删了**：
内容在第一页，不需要第二个入口（表单接口 `/api/form?key=attrs` 还留着，要拆回来随时能用）。

**上级节点自己也点得开**：起源落到「起源」表那张表单、装备与背包落到装备表单、
魔法物品落到魔法物品表单、专长落到专长页、法术落到法术列表——点哪一级都不会撞上
一块「空白占位」。「伙伴与据点」「其他」两条已经删掉（里面那几张表还没做页面，
先不占设计树的位置）。

「起源」下面三行，种族和背景分开：

```
起源
  种族   主要   我选的种族有哪些特性
  背景   起源   我选的出身给什么
```

「其它」（故乡 / 外观 / 个性 + 背景收益）那一栏删了——点上一级「起源」就是这个表单；
「职业特性」那一栏也删了——点上一级「职业」就是那个页面；按等级看特性在下面新加的「职业特性」里。

**种族 / 背景这两页里，上面都锁着一行**：种族 / 亚种 / 出身都在「基本信息」里定，
这里只显示卡里现在的值（跟着一句「在「基本信息」里定」），改不了。抓的东西走最右边的备选区。

这行**跟着「基本信息」里刚选的值走**，不要求先写进表：在基本信息选了「半身人」，
还没点「填入表格」，种族页就已经按半身人过滤了，那格后面会标一个**「还没写进表」**；
写进表之后标记自己消失。

| 页 | 里面是什么 | 能做什么 |
|---|---|---|
| **种族** | 我选的**那个种族**的特性（按卡里的种族类别过滤，比如选了精灵就只有 5 条），搜索框也跟着收成「在「精灵」里搜种族特性…」；种族都锁定了，那排「分类」筛选就收起来，不给看 | 逐条抓进备选区 → 写进 `主要!BT3:BT15`；旁边显示特性槽位用了几个 |
| **背景** | 我选的**那个出身**的全部效果，从规则书里拆出来：属性值 / 专长 / 技能熟练 / 工具熟练 / 装备 / 描述 | 点开看详情和出处；每条右边「+」**抓进备选区**，再从那儿一并写进表（落点见下） |

没定种族 / 出身时两页都会说清楚怎么补：「还没定种族——先在「基本信息」里填」／
「出身还是「自定义背景」——先到「基本信息」里选一个具体出身」。

**出身效果落到哪一格**（`POST /api/background/fill`）。属性值和装备**不用手填**——
卡里 `起源!S4:S7` 本来就是按出身 VLOOKUP 出来的，这两条抓进去也会告诉你「卡里没有对应格子」。
真正会写的是这四样：

| 效果 | 写到哪 | 怎么定 |
|---|---|---|
| 技能熟练 | `主要!B41:B61` 里对应技能打 `O` | 技能名对 `_skillRows`；卡里 `X=无熟练 O=有熟练` |
| 工具熟练 | `起源` 表「熟练工具」下面那几格 | 标签 `B30`，值 `B31/H31/B32/H32`，挑第一个空格 |
| 语言 | `起源` 表「语言」下面那几格 | 标签 `B23`，值 `B24/H24…B28/H28` |
| 专长 | `主要` 表的专长列（`BU19` 起） | 哪一列靠卡内公式反推；名字去掉「（牧师）」这类后缀 |

找不到格子的（属性值 / 装备 / 描述）不会静默丢掉，写完之后一条条列在结果里。
- **其它**——「起源」表剩下的那些（故乡 / 年龄 / 性别 / 身高 / 体重 / 人物形象 / 个性），
  外加卡按出身反查出来的收益（只读）。出身不在这里重复给入口。

「职业」下面两行，跟起源那两行是一个做法（`classinfo` / `classlevel` 两个页面）：

```
职业
  主职业 / 子职业  主要   我选的主职业 / 子职在规则书里是什么样
  职业特性        主要   到这一级为止给了哪些特性（顶上顺带显示等级 / 熟练加值）
```

**主职业 / 子职业页**顶上同样锁着一行（主职业 / 子职业 / 等级，都跟着「基本信息」里刚选的值走，
没写进表就标「还没写进表」）。正文来自 `card_rules.json` 的 `kind=class` / `kind=subclass`，
页面把职业正文最上面那张**核心特质**表拆成一条条，每条右边一个「+」，抓进备选区再一并写进表。
落点分三类：

| 条目 | 落点 |
|---|---|
| 核心特质 | 卡里的**「职业能力」面板**（`主要` 表 `AX11` 往下那块）：卡里已经有同名标签行的（豁免熟练 / 技能熟练 / 武器熟练 / 工具熟练 / 护甲受训 / 起始装备）就补那一行的**描述**；卡里没有的（**主要属性 / 生命值骰**）就占下面第一个空槽，**名称 + 描述一起写**，把面板的空位填满 |
| 技能熟练 | 整条菜单「选择2项：特技、驯兽…」写进面板那一行；具体挑哪几项在页面上**勾选**，勾中的一条条进备选区 → `主要!B41:B61` 对应技能打 `O` |
| 工具熟练 / 语言 | 整条（`任选3项乐器`）进面板；一条条具体的工具 / 语言写「起源」表那几格（跟出身共用） |

「职业能力」面板那两列都是**认出来的**：名称列 = 职业特性那一列（靠卡内公式反推），
描述列 = 表头那一行写着「描述」的那一列——所以 `悲灵 v1.0.12`（`AX` / `BC`）和更早的
版式（名称 `BU`、描述 `BZ`）都能认。面板空槽用完了会明说没写，不会硬挤。

整条菜单（`选择2项：历史、洞悉、医药…`）抓进去时，写面板那一行 + 提醒你
「这是从 5 项里挑 2 项，先在页面上勾选」，不会瞎猜着写。子职另有一条卡：点开就是子职正文。

**职业特性页**顶上显示等级、主职业 / 子职业和算出来的熟练加值（`2 + (等级-1)/4` 向下取整），
正文按「`N级：特性名`」抽出来，只列**到这一级为止**该有的特性——职业和子职合在一起，
子职那几条标「子职」。每条的「+」抓进备选区，写表时落 `主要!AX17:AX77`（跟职业特性页同一个落点）。

树的操作：点名字 = 选中并展开；只有点小三角才折叠。上次离开的节点记在 localStorage，刷新后回到原位。

> 魔法物品这块锚在「主要」表：武器行 30–36（`F31` 同调）、护甲/盾行 38–40、奇物行 41、
> 右侧 `AM38` 是「已同调的装备」汇总。注意 `card\空白卡.xlsx` 是更早的一版模板，
> 这几格的位置不一样（它的奇物在 `L38`，也没有 `AM38` 那块汇总）。

法术页内部两栏：

| 位置 | 内容 |
|---|---|
| 左 | 搜索框 + 筛选（环阶 / 学派 / 职业 / 来源）+ 法术列表 |
| 中 | 点中法术后的完整详情，含「+ 抓进备选区」 |

备选区最下方两块：

- **目标表格**：当前要写进去的那张 xlsx（显示文件名、路径、法术位占用、卡内法术大全条数）
- **新建表格 / 使用已有表格**：都走 Windows 原生「另存为 / 打开」对话框，可以直接在电脑里翻文件夹。
  原生对话框打不开时，还有个「手动选择」，用内置的目录浏览器选表或新建表。

## 运行

**桌面版（推荐）**：双击 `D:\quicklyFind\桌面版\法术速查填表.exe`。
那是个 Flutter 壳（源码在 `D:\quicklyFind\desktop_app`）：它先起本目录编译出来的
`实验区\quickref.exe`，再用原生窗口（WebView2）显示这个界面，关窗时把服务一起收掉。
改了界面 / 数据不用重编壳；改了服务端代码，重新
`dart compile exe bin/quickref.dart -o ..\实验区\quickref.exe` 就行。

```powershell
$env:PUB_CACHE='D:\quicklyFind\.pub-cache'      # 默认 pub 缓存在沙箱外，写不进去
cd D:\quicklyFind\dnd_quickref
dart pub get
dart run bin/quickref.dart                       # 默认自动打开 http://127.0.0.1:8765
```

参数：`--port` `--no-open` `--data <词条目录>` `--card <初始表格>` `--template <空白模板>`
`--workspace <目录>`（指一份自包含目录，该目录下直接有 `web\` 就把它当应用根，
否则当工作区根，去找它下面的 `dnd_quickref\web\`）`--web <目录>`（单独指定界面目录）。

工作区根 / 应用根 / 界面目录 / 词条目录的最终取值，`GET /api/meta` 的 `paths` 里能看到；
界面目录里没有 `index.html` 时不再甩一个光秃秃的 404，而是给一段说明（控制台也会打）。
界面里选过的表格会记在 `.quickref.json`，下次启动直接用它。


## 魔法物品速查

卡里的奇物只有名字 + 同调，正文得从书里来。所以多了一条词条线：

- **数据**：`python tools\extract_magic_items.py` → `dnd-data\magic_items.json`
  （307 条，来自 `rules-text` 里「城主指南2024 › 第七章：宝藏 › 魔法物品详述」，
  按 类别 / 稀有度 分页，标题带英文名，正文头一行写着「奇物，珍稀」）。
- **页面**：设计树「魔法物品」那一页，上半是**速查**——搜索框（名称 / 英文名 / 正文）、
  类别与稀有度的筛选面、结果列表（点一下展开全文，右边「+」抓进备选区）；下半还是卡里
  那几块的编辑格（武器 / 护甲 / 盾 / 奇物的名称、同调、稀有度、部位…）。
- **写进哪**：备选区 → 填入表格 → 奇物名那一列（`主要!L42:L51`，表头写着「奇物」，
  往下一行起 10 格，卡里已有同名会跳过）。同调 / 稀有度 / 部位还是在下半部分手填。

## 已经能填的几条链路

每一条都是「左边查出词条 → 中间看详情 → 抓进最右边的备选区 → 一键写进卡里」，
**写入位置全部由卡内公式反推**，不是写死的格子。

| 页面 | 词条数 | 写进哪里（以 `card\悲灵.xlsx` 为例） |
|---|---|---|
| 法术列表 | 798 | `法术书!X3:X52`、`AC3:AC52`、`AH3:AH52`、`AM3:AM52`（4 组共 200 格） |
| 职业特性 | 2080 | `主要!AX17:AX77`，另加 `主职业=E6` / `子职业=I6` / `等级=O6` |
| 种族背景 | 493，按我选的种族过滤 | `主要!BT3:BT15`（种族 / 亚种 / 出身在「基本信息」里定，这一页不改） |
| 专长 | 229 | `主要!BU19:BU29` |
| 魔法物品（速查） | 307 | 奇物名 `主要!L42:L51`（表头「奇物」往下 10 格） |

`card\空白卡.xlsx` 是另一版式，同一套代码认出来的位置完全不同（法术位 `X3:X52` 一样，
职业特性在 `BU3:BU82`、种族在 `AW31:AW41`、专长在 `AX45:AX53`）——所以换卡不用改代码。

## 填入是怎么做的

1. **输入格是认出来的，不是写死的。** 两条判据：
   - 法术：卡里只要出现 `=IFERROR(VLOOKUP(<单元格>,法术大全!…,2,…))`，那个单元格就是法术名输入格；
   - 其它面板：某张数据表（职业 / 种族 / 专长与据点…）里**成段地引用「主要」表某一列**
     （`IF(主要!AX17="","",主要!AX17)`、`IF(主要!BT3="",0,主要!BT3)`、`IF(ISBLANK(主要!B32),"-",主要!B32)`
     这些写法都算），那一段就是该面板的输入列；`IF(主要!E6="",0,主要!E6)` 这种指向单格的，是「选择格」
     （主职业 / 等级 / 种族…）。

   同一列上连续成段的格子算一段，多段按从左到右、从长到短取。

   你给的卡（悲灵 v1.0.12）认出来是 4 段：
   `法术书!X3:X52`、`AC3:AC52`、`AH3:AH52`、`AM3:AM52`，共 **200 格**。

2. **重复自动跳过。** 卡里已经有同名法术的、以及本批清单里自己重的，都跳过，继续往后填；
   比较用归一化名称（去空白/标点、忽略大小写）。

3. **卡里没有的法术会被点出来。** 名称不在本卡「法术大全」里的，仍会写进格子，
   但界面会列出来（卡内反查出的英文名/专注/仪式会是空的），你可以自己决定留不留。

4. **写前自动备份。** 覆盖已有文件前先复制一份
   `<表名>.备份-YYYYMMDD-HHMMSS.xlsx` 放在同目录（只留最近 10 份）。
   本次刚「新建表格」出来的文件不备份。

5. **外科式写入。** xlsx 就是 zip，只替换目标 `<c>` 单元格的 XML，其余条目（图片、其它工作表、
   样式、数据验证、条件格式）逐字节原样搬运。自检里的实测：

| 验证 | 结果 |
|---|---|
| zip 条目数 | 80 → 80，不变 |
| 内容有差异的条目 | 只有 `xl/worksheets/sheet13.xml`（法术书） |
| 公式数 | 612 → 612，不变 |
| `X3` 右邻的 `Y3` 公式 | 仍在（`=数据表!D2`） |
| 单元格样式 | 保留（写入后 `s="469"` 仍在） |
| 原卡文件 | 字节级未变 |

> 为什么要自己扫 `<c>` 标签：自闭合写法 `<c r="X3" s="469"/>` 会被
> 「匹配到下一个 `</c>`」的正则连后一个单元格一起吃掉。人物卡里 `X3` 右边紧挨着 `Y3` 的公式，
> 踩中就会静默删公式。

## 车卡的选项从哪来

**不发明选项，只读卡自己的清单。** 卡里的 VLOOKUP 只认自己表里列出的名字——选了卡里
没有的种族 / 子职，卡算出来就是空值。所以每个下拉都从卡里读（`lib\data\card_lists.dart`，
全部靠表头定位，换版式不用改代码）：

| 选项 | 卡里的出处 | 现在读到 |
|---|---|---|
| 主职业 / 兼职职业 | `职业` 表里表头为「职业」的那一列 | 19 个 |
| 子职业 | `职业` 表里「职业 × 出处」那块矩阵，**按所选职业过滤** | 战士 9 个 |
| 种族 | `种族` 表里表头为「种族」的那一列 | 60 个 |
| 亚种 | 种族名右边那一排，**按所选种族过滤** | 精灵 5 个 |
| 武器 / 护甲 | `装备` 表里表头为「名称」的那一列 | 43 个 |
| 阵营 | 卡给 `T8` 配的 dataValidation | 10 个 |
| 背景 | `背景` 表 | 38 个 |

两条连带的规定：

- **扩展开关归卡管。** 没开的扩展，卡里那格就是空串（`IF(自定义调整栏!…="O",…,"")`），
  读出来自然没有。想加回来在卡里把开关打开、存一次就行，应用不用改。
- **子职跟着职业、亚种跟着种族。** 主职业填「战士」，子职下拉就只剩战士那 9 个；
  兼职 1 看它自己那一格。种族没选时亚种给空（卡也算不出来）。

卡里找不到这份清单时，才退回词条库的筛选面——`dnd-data` 是兜底，不是依据。
词条页上方的筛选框仍然是词条库的筛选面，那是用来筛「条目」的，跟车卡选项不是一回事。

## 主职业 / 子职 / 出身的规则正文

卡只给了主职业、子职和出身的**名字**，没有正文。正文在 `rules-text\`（规则书语料）里，
两边靠 `dnd-data\card_rules.json` 对上：

- 生成：`python tools\link_card_rules.py`（清单从卡里现读，卡换了要重跑；
  加 `--dry-run` 只打报告）。
  主职业 19 条对上 17 条（`血猎手`、`药剂师` 规则库里没有整篇职业正文）。
  子职 137 条对上 130 条（`游荡剑客`、药剂师的 6 个对不上）；
  出身按卡里那份完整名单（99 条）对上 80 条（拉尼卡公会的 10 个、`继承者`、`深水城贵族`、
  `死魔法区住民` 等对不上）。对不上的在文件里单独列着，不硬凑。
  注意：**查正文按整份名单，下拉里只放核心 16 条**——这是两件事。
- 匹配分几档：同名 → 去掉标题里的出处（`狂野魔法道途（TCE）`）→ 去掉前缀
  （`武僧-神龙宗`、`野蛮人：巨人道途`、`背景-运动员`）→ 归一化 → 人工别名
  （卡里 `幽域追踪者` = 书里 `幽域追猎者`、`巨灵宗主` = `巨灵`）。
  同名的挑一条：目录里挂在本职业 / 本篇下的 > 玩家手册2024 > 层级浅的 > 正文长的。
- 取用：`GET /api/rule?kind=subclass&cls=战士&sub=奥法骑士`、
  `GET /api/rule?kind=background&name=侍僧` → `{found, title, book, crumbs, text}`。
  **基本信息**页选中子职业或出身时，表单底部会出现一张只读的
  规则卡片；靠别名命中的会注明「卡里写作「…」」，库里没有的明说没有。

**写表永远用卡里的写法**，规则书那边的名字只用来查正文。

## 备选区

备选区是**应用级**的一栏，在 `.app` 里跟设计树、主区平级（`index.html` 的 `aside.stage`），
不是塞在某一个页面里的——所以哪一页都在，位置也永远是最右那一列。

```
┌──────────┬────────────────────────────┬────────────┐
│ 设计树    │  当前页（列表 + 详情 / 表单） │  备选区     │
└──────────┴────────────────────────────┴────────────┘
```

规则：

- **填的先攒进来。** 表单页（基本信息 / 属性与技能 / 起源 · 其它 / 装备 / 魔法物品）
  里改动过的字段自动进备选区，显示成「分组 · 格子 → 值」。跟卡里当前值一样、或者
  被清空的字段会自己撤下来。
- **词条 / 法术也攒这儿。** 法术、职业特性、种族特性、专长的「+」都抓进备选区，
  列表里标「已在备选区」。点「填入表格」时字段走 `/api/form/fill`、法术走 `/api/fill`、
  词条走 `/api/page/fill`，各写各的。
- **每条记着自己来自哪一页。** 跨页攒的会在备选区里按页分组显示；点「填入表格」按页
  分别写（一页发一次 `/api/form/fill`），一次点完。
- **选表格也在这儿。** 新建表格 / 使用已有表格 / 手动选择三件套跟「填入表格」按钮
  一起放在这一栏底部——页内没有第二个入口了。
- **逐条删 / 清空。** 删一条会把对应的输入框退回卡里现在的值；「清空」是全清。
- **唯一入口。** 页内**填入区已经删掉**（法术页和词条页都没了，列表 / 详情两栏把宽度占满），
  写表只有备选区底部那一个按钮，所以「填 → 攒 → 写」的顺序是固定的。
- 备选区的状态在页面内存里，**刷新或关掉标签页就没了**。

## REST API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/meta` | 法术总数、筛选面、模板路径 |
| GET | `/api/search?q=&lvl=&school=&cls=&src=&limit=` | 检索 |
| GET | `/api/entry?id=` | 单条完整词条 |
| GET | `/api/tray` | 服务端填入区（**界面已经不用了**，留着给脚本 / 旧版本） |
| GET | `/api/table` | 当前表格：法术位、占用、卡内法术大全 |
| GET | `/api/page?key=class\|species\|feat` | 词条页：输入列、选择格、可选值、筛选面 |
| POST | `/api/page/fill` `{key,names,若干选择格}` | 写进「主要」表（跳过重复） |
| GET | `/api/rule?kind=class&name=战士` / `?kind=subclass&cls=战士&sub=奥法骑士` / `?kind=background&name=侍僧` | 卡里的名字 → 规则书正文 |
| POST | `/api/background/fill` `{effects}` | 出身效果：技能打 `O`、工具 / 语言写「起源」表 |
| POST | `/api/class/fill` `{effects:[{label,text,panel}]}` | 职业效果：`panel:true` 的写卡里「职业能力」面板（有同名行补描述，没有就占空槽），技能 / 工具照出身那两处写 |
| POST | `/api/table/open` | 原生「打开」对话框 → 换目标表格 |
| POST | `/api/table/new` | 原生「另存为」对话框 → 用模板新建一份 |
| POST | `/api/table/use` `{path}` | 直接指定已有表格 |
| POST | `/api/table/create` `{dir,name}` | 用模板新建到指定位置（手动选择用） |
| POST | `/api/fill` `{names?}` | 把法术填入区（或指定名字）写进当前表格 |
| GET | `/api/fs?dir=` | 目录列表（手动选择用） |
| POST | `/api/reveal` `{path,dir}` | 资源管理器里打开 |
