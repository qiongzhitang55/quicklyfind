## B1 下拉「只能选一次」

**现象**

任意下拉（主职业 / 子职业 / 出身 / 阵营 / 亚种，以及属性、技能那些 `X/O` 勾选格）选中一次之后，
再点开列表就只剩刚选的那一项，其它选项全都点不到，像是坏了。

**复现步骤**

1. 打开「基本信息」页
2. 点「主职业」下拉，选「牧师」——正常，值变成牧师
3. 再点「主职业」下拉
4. 列表里只剩「牧师」一项，想改选「德鲁伊」点不到

**根因**

`web/app.js` 里有两个互不相干的功能，被同一个事件串在了一起：

```js
// 第 1509 行：输入框上的 input 事件 → 用来做「打字筛选」
input.addEventListener('input', () => comboFilter(box));
```

```js
// 第 1567 行：选中一个选项时执行的函数
function comboPick(box, value) {
  const input = box.querySelector('input');
  const old = input.value;
  input.value = value;
  ...
  if (old !== value) {
    input.dispatchEvent(new Event('input', { bubbles: true }));   // ← 问题在这
    input.dispatchEvent(new Event('change', { bubbles: true }));
  }
}
```

`comboPick` 为了通知表单「这个字段变了」，给输入框发了一个假的 `input` 事件。
但这个假事件被「打字筛选」接住了——`comboFilter` 一看输入框里写着「牧师」，
就把所有不含「牧师」的选项全部设成 `display:none`（第 1531–1538 行）：

```js
const q = input.value.toLowerCase();
const show = !q || v.toLowerCase().includes(q);
opt.style.display = show ? '' : 'none';
```

**为什么只读的下拉会彻底卡死**：这些字段的输入框带 `readonly`（只能从列表里挑，不能打字），
所以没办法手动删掉里面的字来清掉筛选，这个筛选就永远留着了。
能打字的那几种（种族、武器，选项超过 30 个）可以靠手动删字恢复，但体验同样有问题。

**建议改法**

删掉第 1575 行那一句，只保留 `change`：

```diff
-    input.dispatchEvent(new Event('input', { bubbles: true }));
     input.dispatchEvent(new Event('change', { bubbles: true }));
```

已经核对过：`#fmSections` 上监听 `input` 的那几件事（同步备选区 `syncStage`、
刷新联动选项 `refreshDependent`、刷新规则卡 `scheduleRuleCard`）在 `change` 上都有对应处理，
所以删掉不会丢功能。改完「选值」和「打字筛选」就彻底分开了。

**影响面**

所有只读下拉。这是最常用的控件之一，优先级最高。

## B2 备选区单条删除没反应

**现象**

备选区里每一条右边有个 `×`，点了没反应，条目还在，计数也不变。
（右下角的「清空」是正常的，所以这个 bug 容易被忽略。）

**复现步骤**

1. 随便填一个字段（比如在基本信息里选个主职业），它会进备选区
2. 点那一条右边的 `×`
3. 数字不变，条目还在

**根因**

每一行生成出来是这样的（第 1316–1330 行），注意 `data-del` 写在**按钮**上，
行本身只有 `data-id` / `data-field`：

```js
<div class="trow" data-kind="field" data-key="basic" data-field="cls">
  <div class="n">...</div>
  <button class="link danger" data-del="cls">×</button>
</div>
```

而删除的处理函数（第 1955–1980 行）是从**行**上取值的：

```js
const btn = ev.target.closest('[data-del]');
const row = btn.closest('.trow');
const key = row.dataset.key;
const del = row.dataset.del;      // ← 行上没有这个属性，永远是 undefined
```

`del` 是 `undefined` 之后，下面的过滤条件 `e.field === del` 永远不成立，于是一条都删不掉。
**代码不报错、静悄悄地什么都不做**，这是最难查的一类 bug。

**建议改法**

```diff
-  const del = row.dataset.del;
+  const del = btn.dataset.del;
   if (!row) return;
```

（顺手加的 `if (!row) return;` 是防御：以后万一有别的 `data-del` 按钮不在 `.trow` 里，
`row.dataset` 会直接抛错。）

**影响面**

备选区里所有类型的条目（字段 / 词条 / 效果）都删不掉。

## B4 换了出身，「背景收益」显示的还是旧出身的文案

**现象**

基本信息里把出身改成「工匠」，去起源页看「背景收益」，
四行显示的还是「自定义背景」的通用提示（"见注释，或自选至多三项" 等），
而不是工匠真正的「力量、敏捷、智力 / 巧匠 / 调查与游说」。

**复现步骤**

1. 打开基本信息页，把「出身」改成「工匠」，填入表格
2. 切到「起源」页，看最右边的「背景收益」四行
3. 显示的还是旧文案（卡里 E6 已经是「工匠」了）

**根因**

卡里的公式链是这样的：

```
起源!E6  （出身）
   ↓  背景!I2 = 起源!E6
背景!J2 = IFERROR(VLOOKUP($I$2, 背景!$B$2:$H$141, 2, FALSE), "")
   ↓  起源!S4 = 背景!J2
起源!S4  （背景收益：属性值）
```

公式本身没问题，问题在**缓存值**。程序是「外科式写入」：只替换目标格子的 XML，
既不重算公式，也没有公式引擎。所以把 `起源!E6` 改成「工匠」之后，
依赖它的那些格子还停留在上一次 Excel 计算的结果上。

实测：`新人物卡.xlsx` 里 `起源!E6 = 工匠`（程序写进去的），
但 `背景!I2` 的缓存值仍然是「自定义背景」，`J2` 自然也是旧文案。

**建议改法**（二选一）

- **省事的**：写入成功后在界面上提示一句「已写入，请用 Excel 打开一次以刷新公式」。
  诚实、安全、改动小。
- **彻底的**：应用自己按出身算收益，不读卡里的缓存值。但要自己实现规则，成本高、容易算错。

**影响面**

所有依赖卡里公式的显示都可能受影响，目前确认的是「背景收益」这一条链。
**数据本身没写错**，用 Excel 打开一次就会变对。

## B6 出身效果里的「专长」不查重

**现象**

卡里的专长列已经有「巧匠」了，把出身的「专长」效果抓进备选区再填入表格，
它会在**后面一格再写一遍**「巧匠」，卡里出现两个同名专长。

**实测**

```
写入前：主要!BU19 = 专注重击、BU20 = 云端漫步者、BU21 = 巧匠
写入后：BU22 = 巧匠   ← 又写了一条
```

**根因**

出身效果写专长时用的是 `freeIn()`（`bin/quickref.dart:985–994`），
它只判断「这一格是不是空的」，**不判断这个名字是不是已经在列里了**：

```dart
String? freeIn(String sheet, List<String> slots) {
  for (final c in slots) {
    if (writes[sheet]?.containsKey(c) ?? false) continue;
    if (p.cellText(sheet, c).trim().isEmpty) return c;   // 只看空格
  }
  return null;
}
```

**对比**：词条页（种族 / 职业特性 / 专长 / 法术）走的是另一条路 `fillSpells()`，
**有**查重。实测把卡里已有的「幸运」「勇气」「半身人灵巧」一起提交，三条都被正确跳过：

```

```

所以同一个「填入表格」按钮，走词条那条路会查重，走出身效果这条路不会。

**建议改法**

给专长那一段加一句「列里已有同名就跳过」，或者直接复用 `fillSpells()` 那套查重。

**影响面**

只有出身效果里的专长会重复。法术 / 种族特性 / 职业特性不受影响。

**根因**

## B12 表格版式里，有候选的文本框不给下拉

**现象**

「装备与背包 · 武器」页里，`武器名` 是一格一格的表格。点它、双击它、按方向键——
**没有任何候选列表**，只能自己一个字一个字打。护甲名、盾牌名同样。
「魔法物品」页里的武器名也是同一个毛病（它们本来就是同一块格子）。

**复现**

1. 设计树 →「装备与背包 · 武器」
2. 点第一个「武器名」输入框

**根因：候选被前端丢掉了**

服务端其实是给了候选的，我直接问过接口：

```
/api/form?key=gear
  武器名 | 候选数=43 | 徒手打击、短棒、匕首、巨棒、手斧 …
  护甲名 | 候选数=29 | 法师护甲、大法师法袍、武僧、野蛮人、龙术 …
/api/form?key=magic
  武器名 | 候选数=43 | （同上）
```

界面里那一格的真实 DOM 是这样的（我抓的实时结构）：

```html
<td><input data-field="gear_B32_0" value="" title="武器名 B32" type="text"></td>
```

**一个 `<input>`，没有 `.combo` 外壳、没有 `.combo-pop`、候选数 0** ——43 个候选就这么没了。

问题出在 `web/app.js` 的 `fieldHtml()`。它按顺序判断：

```js
if (f.kind === 'label') return ...;
if (f.kind === 'readonly') return ...;
if (f.kind === 'toggle') return comboHtml({...});        // ← X/O 勾选格走这里，正常
if (inTable) {
  if (asSelect(f)) return comboHtml({...});              // ← asSelect 要求 kind === 'select'
  return `<input data-field=... type="text" ...>`;       // ← 候选在这里被丢掉
}
if (f.options.length) return comboHtml({..., editable: true});   // ← 非表格版式才有这一条
```

武器名这批字段是 `kind: 'text'`（能自己打字），又落在表格版式里（`row` 有值），
`asSelect()` 对它们返回 false，于是直接走到最后那个裸 `<input>`，
**而"有候选就渲染成下拉"那段代码在下面，表格版式根本走不到。**

**建议改法**

在表格版式的分支里补一条（跟下面非表格版的写法保持一致）：

```diff
   if (inTable) {
     const t = `title="${esc(f.label)} ${esc(f.cell)}"`;
     if (asSelect(f)) {
       return comboHtml({ field: f.field, value: f.value, options: f.options,
                          emptyLabel: '·', title: `${f.label} ${f.cell}`, narrow: true });
     }
+    if (f.options && f.options.length) {
+      return comboHtml({
+        field: f.field, value: f.value, options: f.options, editable: true,
+        type: f.kind === 'number' ? 'number' : 'text',
+        title: `${f.label} ${f.cell}`, narrow: true,
+      });
+    }
     return `<input data-field="${esc(f.field)}" value="${esc(f.value)}" ${t} ...>`;
   }
```

**注意别搞错**：基本信息页的六项属性 / 技能表里那些 `X/O` 熟练格**是正常的**
（我实测过，它们有 3 个候选）。因为 `kind === 'toggle'` 的判断在 `inTable` 之前，
早就返回了。受影响的只有"能自己打字的文本 + 有候选 + 表格版式"这一种组合。

**影响面**

| 页面 | 受影响的字段 | 丢掉的候选 |
|---|---|---|
| 装备与背包 · 武器 | 武器名 ×5、护甲名、盾牌名 | 43 / 29 个 |
| 魔法物品 | 武器名 ×5、护甲名、盾牌名（同一批格子） | 43 / 29 个 |

## B15 写含控制字符的文本会写坏 xlsx（最严重的一条）

**现象**

只要写进去的文字里含有一个不可见的控制字符，生成的 xlsx 就**不是合法的 XML 了**——
Excel 会打不开，或者弹出"文件已损坏，是否修复"。

**复现**

```
POST /api/page/fill  {key:'feat', names:['测试\u0001名字']}
→ 服务端回 200，写入 BU22
→ 但文件里的 XML 变成了：
   <c r="BU22" s="515" t="inlineStr"><is><t xml:space="preserve">测试␁名字</t></is></c>
                                                        ^^^ 裸的 U+0001
→ 用 XML 解析器读这个 sheet：ParseError: not well-formed (invalid token)
```

实测结果：`整个 sheet 里非法控制字符数: 1 码位: ['0x1']`，解析直接失败。

**根因**

`lib/xlsx/patcher.dart:19` 的转义函数只处理了四个标记字符：

```dart
String xmlEscape(String s) => s
    .replaceAll('&', '&amp;')
    .replaceAll('<', '&lt;')
    .replaceAll('>', '&gt;')
    .replaceAll('"', '&quot;');
```

但 **XML 1.0 不允许大部分控制字符**：只有 `\t`(U+0009)、`\n`(U+000A)、`\r`(U+000D) 能直接出现，
U+0000–U+0008、U+000B、U+000C、U+000E–U+001F 全是非法的。
Excel 自己的做法是转成 `_x0001_` 这种形式，而这里什么都没做，直接原样写进 XML。

**这不是理论问题**：从网页、PDF、Word 里复制文字时夹带不可见控制字符非常常见
（最常见的两个是 U+000B 垂直制表符 和 U+0001）。
用户粘贴一个法术名，卡就可能被写坏。

**建议改法**

在 `xmlEscape`（或写入前一层的 `writeCells`）里，把 XML 非法的控制字符处理掉：

```dart
String xmlEscape(String s) {
  final cleaned = s.replaceAll(RegExp(r'[\u0000-\u0008\u000B\u000C\u000E-\u001F]'), '');
  return cleaned
      .replaceAll('&', '&amp;')
      .replaceAll('<', '&lt;')
      .replaceAll('>', '&gt;')
      .replaceAll('"', '&quot;');
}
```

（想更贴近 Excel 的话，可以按它的约定转成 `_x0001_`；直接删掉通常也够用。）

**影响面**：任何写入路径（法术 / 词条 / 表单字段都经过 `writeCells`）。
虽然每次写入前都有备份、卡能恢复，但"程序把卡写坏"这件事必须优先修。

工匠的工具熟练，规则书原文是「选择一种工匠工具（参见第六章）」——一句让人自己挑的指令。
程序把这整句原样写进了卡里的值格。

实测的堆积过程：

```
起源!B31 = 选择一种工匠工具（参见第六章）   ← 上一次写入留下的
起源!H31 = 选择一种工匠工具（参见第六章）   ← 这次又写了一遍（B31 已占）
起源!B32 = 书法工具                        ← 换成侍僧后，往后挪到第三格
```

这是「把菜单抄进卡里、提醒你自己挑」的做法（跟职业面板那里的处理一致），
但代价是：值格里不是工具名而是一句话，而且它会永久占掉一格，换出身也不清（见 B7）。

**状态：已修（2026-09-28）**。改成「等你挑好具体工具再写」：

- **服务端**：`planBackgroundEffects` / `planClassEffects` 遇到这种指令句（`isConcreteAssignment()`
  为 false）只回一条提示，**不写值格**——值格里从此只有 `铁匠工具`、`长笛` 这种具体名字；
- **界面**：背景页的「工具熟练 / 语言」如果是这种句式，不再给「+」，改给一个输入框
  （背景提示「写具体工具，例如：铁匠工具」），挑好写进去再按「+」才进备选区；
- **判定**：`lib/util/text.dart` 的 `isConcreteAssignment()`，词表是
  `选择|任选|自选|挑选|所选|参见|见第|一种|一门|一项|一套|两个|两门|两项|但不能说|你所说|理解`。
  词条库现有 45 条「工具熟练 / 语言」实测：20 条具体名字正常写、25 条指令句全拦住。
  界面那边（`web/app.js` 的 `MENU_HINT`）是同一份正则，改的时候两边一起改。

顺带解掉了这条 bug 的根子：以前指令句会永久占掉一格（`起源!B31` 那种），
现在空格子不会被这种句子吃掉，B7 的"换出身堆脏"也就少一个来源。

## O7 同时写同一张表没有加锁（未复现，但理论存在）

每个写入接口都是「读出整个 xlsx → 改 → 写回」：

```dart
final patcher = XlsxPatcher.open(await src.readAsBytes());   // 读
...
List<int> bytes = await src.readAsBytes();                    // 又读
... writeCells ...
await src.writeAsBytes(bytes);                                // 写回
```

两个请求如果交错（A 读完、B 读完、A 写、B 写），后写的会把先写的覆盖掉。

**实测**：同一时刻发 2 个、再发 6 个写入请求（分别写不同页面），
**发出的请求全部落盘，没有丢数据**。所以现实里撞上的概率不高，
但这个代码路径上确实没有锁。真要保险，可以在写入时加一个串行队列。

**状态**：未复现，仅记录。

## 新增功能（2026-09-27）

### 一、换卡时的完整初始化

**原来**：换目标表只清了「词条页」的缓存，备选区和表单里的东西还是上一张卡的——
换完卡直接点「填入表格」，会把上一张卡挑的法术写进新卡。

**现在**：三个换表入口（新建表格 / 使用已有表格 / 手动选择）统一走 `afterTableChange()`，
而且顺序是固定的——**先把上一张卡从工作区里拿出去，再挂上新卡**：

1. `unloadCardState()`：清空备选区、表单数据、各词条页缓存、魔法物品速查、卡内技能清单
2. 挂上新卡
3. 重新读表 → 重画设计树 → 把当前停留的那一页对着新卡重读一遍

「初始化这张卡」和「读卡」执行前也会先调 `unloadCardState()`，
确保操作的是新卡、不会把上一张卡的东西带进来。

服务端同步加了 `_dropTableCaches()`：表信息、各表单、各词条页的识别结果一起丢掉，
不再只靠「路径 + 修改时间」的戳被动失效。

### 二、「初始化这张卡」

备选区底部新增了一个红色按钮（在「读卡」旁边）。点了先弹确认框，确认后**把这张卡清成空卡**：

- **所有填过的字段 → 空**：角色名 / 玩家 / 主职业 / 子职业 / 等级 / 经验 / 种族 /
  亚种 / 阵营 / 信仰 / 六项属性值 / 技能额外修正 / 武器名 / 护甲名 / 盾牌名 /
  奇物名 / 加值 / 故乡 / 年龄 / 性别 / 身高 / 体重 / 人物形象 / 个性 / 理念 /
  羁绊 / 缺陷 / 背景故事
- **所有「熟练」格 → `X`**：卡里的约定是 `X` = 无熟练、`O` = 有熟练。
  覆盖技能 18 格、六项豁免 6 格、武器熟练 5 格。
- **所有「是 / 否」格 → `否`**：同调、着装这类。
- **所有词条 → 空**：法术位、职业特性、种族特性、专长、魔法物品，
  外加起源表的工具熟练与语言。
- **出身 → 「自定义背景」**：那是卡自己的「没选出身」状态（取值来自空白模板）。

**不动的**：

- 卡里的公式格
- 卡自己的结构行——职业能力面板那 6 行标签（豁免熟练 / 技能熟练 / 武器熟练 /
  工具熟练 / 护甲受训 / 起始装备）、种族页的「生物种类 / 体型 / 速度」
- 卡按出身反查出来的「背景收益」那四行（是公式，会自己算）

**三道保险**，保证不误伤：

1. 公式格跳过（`patcher.formulaRefs()`）
2. 以**空白模板**为准：模板里同一列开头那几格非空的（就是卡的结构行），跳过
3. 只清「内容能在对应词条库里找到」的格子，认不出来的列进返回的 `kept` 里报告

写入前照例自动备份。执行前会**先把工作区清空**（见下），免得上一张卡留下的备选区掺和进来。

### 三、「读卡」

**「导入即读卡」**：换到哪张卡（`新建表格` / `使用已有表格` / `手动选择`），
那张卡里已有的内容就自动进备选区——不用再单独点一次按钮。备选区里现在是什么，
就是这张卡里填了什么。备选区底部那个「读卡」按钮留着当手动重读用（比如你往备选区
里加了别的东西之后，想回到"这张卡现在的内容"）。

- 服务端 `GET /api/card` 读出两类东西：
  **表单字段**（身份 / 等级与职业 / 起源 / 属性与技能 / 装备 / 魔法物品里所有填过的格子）
  和**词条**（职业特性 / 种族特性 / 专长 / 魔法物品 / 法术）。
- **跟空白模板一样的不算"填过"**：`熟练 = X`、`出身 = 自定义背景`、`初始值 = 10`
  这类默认值会被滤掉（否则新建一张空卡读出来就是 43 条噪音）。实测：空白模板读出 **0 项**，
  填好的「琼脂糖」读出 **12 字段 + 12 词条 = 24 项**（滤掉前是 61 项）。
- 词条会拿名字回词条库找 id，这样列表上的「已在备选区」能对上号。
- 客户端**先把上一张卡的东西清出去**（`unloadCardState()`），再放新的——
  读卡是「替换」备选区，不是往上堆。
- 换完卡会提示「已切换目标表格：X，并把这张卡里的 N 项读进备选区」；空卡则提示
  「（这张卡是空的，备选区没东西）」。
- 启动时**不**读：打开工具时备选区还是空的，第一次「使用已有表格 / 手动选择」才读。

> **「搬卡」那条路没了。** 9/27 写的「读卡 A → 换到新卡 → 初始化 → 填入表格」，
> 其实从写下来那天起就是坏的——换卡第一步 `unloadCardState()` 就把刚读进来的东西清空了。
> 现在换卡会拿新卡的内容顶替备选区（这正是"导入即读卡"要的），所以跨卡搬运这条路
> 依旧不通。真要在两张卡之间搬内容，得单独做一个「把备选区锁住」的开关——有需要再说。

### 四、顺手修的

- 手动选择里手打一个坏路径时，`/api/fs` 会抛异常、界面显示成一段乱码般的错误。
  现在返回 `{exists:false, error:'这个路径不对：…'}`，界面照原样显示这句话。
- 点设计树回「法术列表」时不会重画列表，导致上面的「已在备选区」标记是旧的。
  现在回去时会重画一次。

## 武器 / 护甲 / 盾 / 奇物那几块的默认值：数字清空、下拉统一 X（2026-09-28）

用户截图报的：「装备」页的武器表里有 5 个 `O`（武器熟练）、护甲 / 盾那两行有 `否`（着装）

是 / 否 与 X/O 统一成 X**。

查过之后确认这些值不是程序写进去的，是**卡自己的默认值**：

| 格子 | 含义 | 原值 | 现在 |
|---|---|---|---|
| `主要!W32:W36` | 武器熟练（`X/O`） | `O` | `X` |
| `主要!F32:F36` | 武器同调（`X/O`） | 空 | `X` |
| `主要!L32:L36` | 武器加值（数字） | 空 | 空（写之前是空就不动） |
| `主要!P40` / `AP40` | 护甲 / 盾的同调（`X/O`） | 空 | `X` |
| `主要!U40` | 护甲加值（数字） | 空 | 空 |
| `主要!AS40` | 着装（是/否） | `否` | `X` |
| `主要!AQ40` | 盾牌 AC（数字） | `2` | 空 |
| `主要!P42:P50` | 奇物同调（`X/O`，v1.0.12 是 `P42:P51`） | 空 | `X` |

**为什么 X 是安全的**（卡里的公式都按「等于 是 / O」判定，X 落在「没有」那一支）：

- `装备!S21 = IF(主要!F32="O",1,0)` —— 同调计数；X = 没同调
- `装备!AZ2 = …+IF(主要!W32="O", 主要!$S$3, 0)+…` —— 武器攻击加值；X = 不加熟练
- `主要!C23 = SUM(AF40,AI40,G23,IF(AS40="是",AQ40,0))` —— AC；着装 = X 时盾牌 AC 不计入，等价于「否」
- 唯一被影响的是 `数据表!BQ27 = IF(主要!AS40="否","",6)`：着装从 `否` 变 `X` 后它从空变 `6`。
  全簿没有任何公式引用 `BQ27`（grep 过），是条死数据，不影响显示。

**改法**：`tools\make_blank_template.py` 扩了一段 `build_edits()`——从作者原始卡生成基准空白卡时，

## B21 点「基本信息」要么像跳到了别处、要么等四秒（2026-09-28）

**现象**（用户报的）：在设计树里点「基本信息」，有时候看着像跳到了别的页面去，
而且那个界面出得特别慢。

**根因**（两处叠在一起，实测用户当时正跑着的那个服务）：

1. **前端每次点都强制刷新**：`selectNode()` 里对表单页写的是
   `if (!formState.loaded) loadForm(); else loadForm(true);`，也就是第二次以后每次都带
   `refresh=1`。请求还没回来时 `viewForm` 里还是**上一页的 DOM**（装备页 / 魔法物品页），
   于是这四秒里看到的是别的页——正是「像跳到别处」。
2. **服务端那一页本来就慢**：`/api/form?key=basic&refresh=1` 实测 **3985 ms**（用户机器上
   正在跑的那个服务，连续两次都是 3.9 s）。慢在 `patcher.cellText` / `_writable` /
   `_cellExists`：每问一个格子就把整张「主要」表的 XML（300 KB）重扫一遍，
   而基本信息页有 160 多个字段；`XlsxPatcher` 每次请求还要重新解一遍 zip
   （`/api/card` 一次要读 4 张表单 + 4 个词条页 + 法术位，就是 8 次解包）。

**改法**：

| 位置 | 改了什么 |
|---|---|
| `lib\xlsx\patcher.dart` | 新增按表缓存的 `cells(sheet)` / `cellNode(sheet, ref)` / `hasCell` / `isWritableCell`；`cellText`、`formulaRefs`、`columnAll`、`linkedBlocks`、`selectorGroups` 等原来每次 `scanCells(sheetXml(...))` 的地方全改成走缓存（一张表只扫一次） |
| `bin\quickref.dart` | 新增 `_tablePatcher(path)`：目标卡按「路径 + 修改时间 + 大小」缓存解析结果，表单页 / 词条页 / 法术位共用；写盘之后统一 `_dropTableCaches()`（连带丢掉解析缓存），换卡同理 |
| `web\app.js` | `loadForm()` 加请求序号：慢的请求回来晚了就丢掉，不覆盖当前页；换表单前先 `formPlaceholder()` 把上一页的 DOM 换成「正在读这张卡…」，不再让人看到别的页；同一张表单已经画好就不重画（也免得把填了一半的输入冲掉） |

**实测（同一台机器，工作区 card\悲灵.xlsx）**：

| 接口 | 改前 | 改后 |
|---|---|---|
| `/api/form?key=basic&refresh=1` | 3985 ms（用户那个服务） / 4134 ms（本地） | **86 ms** |
| `/api/form?key=attrs` | 3595 ms | 23 ms |
| `/api/card` | 2478 ms | **540 ms** |
| `/api/page?key=class` | 699 ms | 371 ms |

浏览器里真点过一遍（Codex 内置浏览器 + 无障碍树）：从「魔法物品」点回「基本信息」，

### 补：小窗「关不掉」（2026-09-28）

用户报：「悬浮窗关不掉」。查下来是**拖拽状态没清干净**：

- `wirePopDrag()` 原来把 `drag` / `size` 放在 IIFE 的局部变量里，靠 `mouseup` 收尾。
  但 WebView2（桌面版外壳用的离屏合成）里 `mouseup` 会丢 —— 实测用自动化拖动时就没收到。
  于是 `drag` 一直是「拖拽中」，之后每一次 `mousemove` 都把窗口挪到鼠标底下：窗口**粘在鼠标上**，
  想点右上角的 × 时窗口先跑掉了，看起来就是「关不掉」。
- 改法：状态提到模块级的 `popDrag = {drag, size}`，三处兜底 ——
  ① `hidePop()` 里直接清掉；② `mousemove` 里发现 `e.buttons === 0`（键都松了）就结束拖拽，**这一帧不再挪窗**；
  ③ `window` 的 `blur`（切窗口 / 点任务栏）也清。
- 顺手把关闭按钮做大做明白：原来是个光秃秃的 `×`，现在是带边框的按钮 **「✕ 关闭」**（tooltip 写着「关闭（Esc 也行）」），
  标题条上的按钮也不再被当成拖动起点。

实测（这个环境里鼠标事件正好会丢 mouseup）：拖过窗口之后再点「✕ 关闭」→ `#pop.hidden = true` ✓；
鼠标没按着时窗口不再跟着跑。

### 再补：真正的原因 —— `display` 把 `hidden` 顶掉了（2026-09-28）

用户回「按关闭还是关不掉」。这次查对了：**`pop.hidden = true` 设了，但 `.pop { display: flex }`
比 `[hidden]` 的浏览器默认规则（`[hidden] { display: none }`）优先级高 —— 属性生效了、元素照样画出来。**
所以前面几次「关掉了 ✓」都是假的：我只查了 `hidden` 属性，没查 `getComputedStyle().display`。

这个坑项目里其它地方早就踩过并各留了一条 `X[hidden] { display: none }`（`.modal[hidden]`、
`.lookup[hidden]`、`.pane[hidden]`、`.combo-pop[hidden]`、`.tree-kids[hidden]`、`.tabs[hidden]`、
`.stale[hidden]`…），新写的 `.pop` 漏了。补上 `.pop[hidden] { display: none !important; }`

那正是 `#pop` 带着 `hidden` 却被 `display:flex` 画出来的样子。

| 点一条法术 | false | flex | 560×518，看得见 |
| 点「✕ 关闭」 | true | **none** | **0×0** |
| 拖一把之后再点关闭 | true | none | 0×0 |

### B22 待办里的「六项属性」「技能熟练」永远是 0

**现象**：卡里 `I13:I18` 已经有 15/14/13/10/12/8、`B40/B52/B56/B60` 都打了 `O`，接口
`/api/form?key=attrs` 返回也对，待办页却写「六项属性 0/6 有值」「技能熟练 0/2」。

**根因**：`loadProgress()` 里 `a = formFieldsMap(attrs)` 拿到的是个 **Map**，可找属性 / 技能格
的两段循环写的是 `for (const s of (a.sections || []))` —— Map 上没有 `.sections`，`|| []`
兜出一个空表，于是 `attrCells` / `skillCells` 恒为空：技能数恒为 0；属性那行
`filled === attrCells.length` 是 `0 === 0`，还判成**已完成**（✓ 绿）。

**改法**：两处都改回 `attrs.sections`（`web/app.js:212`、`:228`）。

**怎么验的**：填了 力量 16 / 体质 14 之后，待办显示「六项属性 2/6 有值」且是 ○（不再是 ✓）；
在职业页勾上察觉 + 求生，显示「技能熟练 2/2 ✓」。

### B23 护甲名 / 盾牌名的下拉候选是武器的「词条」列

**现象**：装备页「护甲名」「盾牌名」的下拉里全是 `轻型` / `双手` /
`投掷（射程 20/60），多用（1d8）` 这类武器特性词，两个字段候选一模一样（各 26 个）。
手输（`链甲` / `盾牌`）能正常写进卡，坏的只是候选。

**根因**：`_armorNames()` 读的是写死的 `装备!AP12:AP48`。v1.0.12 那张卡上 `AP` 确实是
「装备名称」，但 v1.1.1 的 `装备` 表把装备块整体右移了 —— `AP` 变成了武器的「词条」列，
「装备名称」跑到了 `AU`（v1.0.0 是 `AQ`）。

**改法**：改成认表头 —— 找 `装备` 表第 1 行写着「装备名称」的那一列；这一列前半段是盾牌，
`护甲名称` 那个小标题之后才是护甲清单（`装备!BA12` 的 `VLOOKUP(主要!L40, AU12:AY48, …)`
查的就是后面这段）。挪进 `lib/data/card_lists.dart`，跟别的卡片清单放一起
（`CardLists.equipNames()`）。

**怎么验的**：`/api/form?key=gear` → 护甲名 31 个（法师护甲 / 大法师法袍 / 武僧 … 板甲），
盾牌名就一个 `盾牌`；界面上打开两个下拉，内容一致。自检补了两项，67 项全过。

### B24 待办不把「备选区里还没写进表」的字段 / 熟练算进进度

**现象**：把基本信息一整页填好（角色名 / 种族 / 出身 / 阵营 / 主职业 / 等级 / 属性），只要还没点
「填入表格」，待办就还报「角色名 未填」「出身 未定」「等级 1 级」（读的是卡里的旧值）。可同一时刻
种族页 / 职业页会显示「还没写进表」—— 两处口径不一致。

**根因**：`loadProgress()` 只读 `/api/form`（卡里的值）；而种族 / 职业那几页走的是另一条路 ——
`pendingValue()` 会把备选区里攒着的新值盖上去。进度没走这套。

**改法**：`loadProgress()` 里加 `applyStagedFields(map, 'basic')`，把备选区里 `kind: 'field'`
的条目按 `field` 和 `@格子` 两个键盖到表单映射上；技能那几行另外认备选区里的熟练条目 ——
表单勾选是 `kind: 'field'`、出身 / 职业给的整句是 `kind: 'effect'`、种族 / 专长挑出来的单条是
`kind: 'prof'`，三种都算（整句那种按名字包含来认）。

**怎么验的**：不点「填入表格」，只填表单 → 待办立刻显示 角色名=修完验证、主职业=战士、等级=3 级、
种族=人类、出身=士兵、技能熟练=2/2。

### B25 基本信息页的角色名 / 玩家 / 经验值 / 兼职 / 阵营 / 信仰永远挂 ⚠

**现象**：基本信息页这 8 个字段后面永远跟着 ⚠（「这一格没从卡里认出来」），可实际写入正常 ——
角色名 `E3`、玩家 `E4`、阵营 `T8` 都写进去了。

**根因**：`_formFields` 里 `mk()` 帮助函数的 `detected` 参数默认值是 `false`，而这几个纯文本字段
创建时都没传 `detected:`，于是永远被判成「没认出来」。（写入只有 gear / magic 两页看 `detected`，
所以没别的后果，纯粹是界面误导。）

**改法**：`detected` 改成 `bool?`，没明说时按格子自己判断 ——
`cell.isNotEmpty && patcher.isWritableCell(sheet, cell)`。

**怎么验的**：`/api/form?key=basic` 里 14 个字段全部 `detected=True`；界面上 ⚠ 全部消失。

### O8 等级不到 4 级时，专长配额显示「无上限」

**现象**：3 级的角色，专长页那颗配额标签写「专长 0 无上限」；规则上这时是 0 个。

**根因**：`quotasFor('feat')` 在 `cap === 0` 时跟「不计数的那些页」（职业特性 / 种族特性）走同一条
显示分支，一律写「无上限」。

**改法**：配额条目支持一个可选的 `zero` 文案；专长那条在等级不到 4 级时给「N 级还没有专长」，
等级没填时给「等级还没填」，其余页照旧「无上限」。

**怎么验的**：3 级 → 「专长 0 / 0 3 级还没有专长」。

### O9 `species.json` 的「生物种类 / 体型 / 速度」取自错位的行

**现象**：选「人类」时，种族特性词条的小窗里写着「你是类人生物。如果有任何前提或效果需要你作为
一个**侏儒（Gnome）**，你也被视作侏儒。」「体型：**小型**」。

**根因**：`dnd-data\species.json` 是拿 `card\grids\*.json`（**米瑞尔那张老版式卡** dump 出来的网格，
见 O1）抽的。`种族` 表里 A 列是「种族 + 亚种」的大清单，而 E/F/G/H 那四列（E 是这一块自己的
名单，F/G/H 是生物种类 / 体型 / 速度）是**另一份名单**，两边行号不对齐 —— `extract_species()`
却按 A 列的行号去读 F/G/H，于是每个种族都配到了隔几行之外的元数据。（米瑞尔那张卡上 A24 是
「人类」，而 F24/G24 已经是地底侏儒的「…侏儒…」/「小型」。）

**改法**：`tools/extract_species_class.py` 里先按名字在 E 列建一张「名字 → 行号」的表，`base_meta`
按 `base["name"]` 去查（96 个基础种族里只有 曼德拉 / 半血裔 / 巫咒之子 / 复生者 4 个不在 E 列，
退回原行号）。顺手删掉一个没人用、而且本来就读错列的 `通用特性` 键。

**怎么验的**：重导到临时文件后逐条比 —— `class_features.json` **零差异**（2080 条，顺序和 id 都
一样）；`species.json` 493 条里 438 条变了，变的全是 `fields`（生物种类 / 体型 / 速度）和 `tags`，
**没有任何字段从有变空**。人类现在是「类人 / 中型(约4-7尺高)或小型(约2-4英尺高)，在选择此种族时
决定」，地底侏儒保住它自己那句侏儒文案；界面上重新点开人类词条，显示一致。

**没动的一处**：「戏法」那条职业特性的名字在**卡里**就写作 `"戏法"`（带引号，`职业!C127`），
不是程序加的，写进卡也照原样写。要改得先改卡。
